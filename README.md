# literate-octo-ai — система ведения проекта человек + AI-агент

Замороженный слепок реальной системы, в которой человек и AI-агент вместе
ведут промышленный проект: файловая структура, инструкции, устав, журнал,
таск-трекер, реестр скиллов. Всё это выросло за время живой работы над
data-проектом; здесь оно очищено от проектной специфики и сохранено как
переиспользуемый каркас.

**Это не шаблон «сделай как я», а рабочая система**: каждое правило здесь
появилось после конкретной ошибки, и у большинства правил в тексте написано,
какой именно.

## Из чего состоит

```
.
├── AGENTS.md          # главная инструкция агенту: как жить в этой директории
├── work_journal.md    # журнал действий (append-only) — формат + образец
├── rules/             # устав: 10 нерушимых принципов, по файлу на правило
├── design_docs/       # витрина опубликованных дизайн-доков (симлинки)
├── skills/            # витрина частых скиллов (симлинки)
├── mastery/           # мастерская: всё, чем координируется работа
│   ├── registry.csv   #   реестр скиллов с триггерами «когда что включать»
│   ├── usage_log.csv  #   боевая метрика: журнал применений скиллов
│   ├── tracker/       #   таск-трекер на CSV (данные; demo-набор)
│   ├── plans/         #   реестр планов
│   ├── design_docs/   #   кухня диздоков (черновики)
│   ├── team/          #   как работает команда: статус, риски, треки, решения
│   └── tools/         #   инфраструктура: локи, проверка ссылок, гейты скиллов
│       └── saturday-tracker/   # ← сабмодуль: UI и ядро записи трекера
├── example-domain/    # шаблон домена — «направления деятельности»
├── agent-infra/       # живой домен: стек Herdr + dsh, Telegram-бот, удалёнка
└── .other/            # преддоменное хранилище для сырых тем
```

Начинать читать — с [AGENTS.md](AGENTS.md): это точка входа для агента и
одновременно самое полное описание системы. Затем [rules/README.md](rules/README.md).

## Ключевые идеи

1. **Журнал append-only** ([work_journal.md](work_journal.md)) — одна строка в
   конце каждого промпта: что просили, что сделал, есть ли кандидат в скилл.
   Правка задним числом запрещена: журнал — история, а не мнение.
2. **Один источник истины** — реестры (трекер, планы, скиллы) не копируются;
   срезы делаются грепом или read-only генерацией. Две копии расходятся всегда.
3. **Таск-трекер на CSV в git** ([mastery/tracker/](mastery/tracker/)) — задачи,
   цели, связи и комментарии в текстовых файлах; правки атомарны, под локом,
   каждая — git-коммит. UI — сабмодуль
   [saturday-tracker](https://github.com/Dgreat21/saturday-tracker).
   Ссылки на карточки заменяют пересказ статуса в чате.
4. **Скиллы с триггерами и боевой метрикой** ([mastery/](mastery/)) — реестр
   говорит, *когда* какой скилл включать (по этапу задачи, по типу артефакта,
   по домену); `usage_log.csv` и `skill_stats.py` отвечают, помогает ли скилл
   на самом деле, — не помогает → «на списание».
5. **Кухня/витрина** — черновики живут в мастерской, наружу выходит симлинк,
   и кладёт его человек, не агент. Публикация — осознанный акт (rule-9).
6. **Параллельные агенты** — мьютексы на файлы (`ctx_lock.py`), git worktree
   на агента, `merge=union` для журнала.
7. **Артефакт или не было** (rule-1) — задача закрыта, когда существует
   файл-артефакт, а не рассказ о работе.

## Быстрый старт: harness внутри Herdr

Идея сборки: **Herdr — стойло, dsh — агент в нём**. Каждый инстанс dsh живёт
в своём Herdr-пейне (инстанс на проект), статусы видны в сайдбаре через
`report-agent`, к стаду можно переподключиться с другой машины.

```bash
# 0. Предпосылки (один раз)
curl -fsSL https://herdr.dev/install.sh | sh   # Herdr (или: brew install herdr)
npx @deepseek-ai/dsh web                       # dsh: первый запуск скачает и поднимет web UI
                                               # ^C после проверки; нужен Node ^22.19 || >=24, плюс jq

# 1. Стадо
herdr                                          # поднять сервер и TUI (оставь запущенным)

# 2. Этот репозиторий
git clone https://github.com/Dgreat21/literate-octo-ai.git
cd literate-octo-ai

# 3. Весь стек одной командой (идемпотентно)
./agent-infra/stack/up.sh
```

`up.sh` создаст Herdr-воркспейс `octo` (cwd = корень репо), поднимет в его
пейне `dsh web --port 3081` — harness работает **внутри** пейна Herdr, — при
наличии `~/.dsh-tg/env` (токен BotFather) добавит пейн Telegram-бота и
прогонит смоук: web отвечает, `herdr agent list` непуст.

Дальше:

- **браузер** — http://127.0.0.1:3081 (web UI harness'а этого репозитория);
- **разовые задачи** — `agent-infra/stack/bin/dsh-herdr "задача"`: headless-прогон
  со статусом в сайдбаре;
- **телефон** — Telegram-бот / SSH+Tailscale reattach / туннель к web UI;
- агент, запущенный в пейне (`HERDR_ENV=1`), сам управляет стадом через
  `herdr`-CLI — так и построена эта сборка.

Подробности, безопасность и отладка —
[`agent-infra/stack/herdr-dsh-instruction.md`](agent-infra/stack/herdr-dsh-instruction.md)
(единственный источник по стеку, rule-3).

## Как переиспользовать

```bash
git clone https://github.com/Dgreat21/literate-octo-ai.git .context
cd .context && git submodule update --init mastery/tools/saturday-tracker
```

Полный `--recurse-submodules` притащит ещё и `agent-infra/vendor/` —
запиненные исходники Herdr и DeepSeek Harness (тяжёлые, нужны только
как референс).

1. Положи директорию рядом с кодом своего проекта (в оригинале она называется
   `.context/` и скрыта от кодового репозитория через `.git/info/exclude`).
2. Замени `example-domain/` на свои направления, обнови таблицу доменов в
   `AGENTS.md` §1.
3. Очисти demo-данные трекера, заведи свои цели и задачи.
4. Подключи `AGENTS.md` в своё агентское окружение (Claude Code, Codex и т.п.
   подхватывают его автоматически).
5. Внешние скиллы-референсы (`anthropics/skills`, `anthropics/plugins`)
   клонируются в `mastery/tools/addons/source/` отдельно — они не входят в git,
   и симлинки витрины `skills/` без них будут битыми (это ожидаемо,
   `check_refs.py` покажет).

## Что было вычищено

реальный журнал (115 КБ), дизайн-доки, командные треки и живые данные трекера.
Структура, правила, инструкции, инфраструктурные инструменты и командные
скиллы сохранены как есть — с реальными формулировками и реальными
пост-мортемами внутри.
