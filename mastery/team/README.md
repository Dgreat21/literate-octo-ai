# team — как мы работаем

Комплект документов планирования и координации команды. В живой системе здесь
лежал план этапа по неделям, сверенный с диаграммой Ганта заказчика; для
публичного слепка содержимое заменено описанием набора.

## Документы

| Файл | Про что | Когда читать |
|---|---|---|
| `STATUS.md` | Где мы по факту: план против репозитория, расхождения | начать отсюда |
| `PLAN.md` | План по неделям с артефактом на каждую задачу | планирование недели |
| `TRACK_<имя>.md` | Личный трек участника: задачи, что делегировать | владелец трека |
| `RISKS.md` | Развилки и риски с владельцами | еженедельно |
| `DECISIONS.md` | Журнал принятых решений | при развилке |
| `<исходник>.xlsx` | Исходная диаграмма Ганта | источник плана |

## Почему team/ живёт в мастерской, а не в корне

Смысловая граница из `AGENTS.md` §1: **домены — над чем работаем** (предмет),
**мастерская — как работаем** (координация). Команда — это «как», поэтому
`team/` здесь.

## Правило приёмки

**Задача закрыта, когда есть артефакт-файл**, а не когда есть рассказ о
работе (rule-1). В живой системе первый же аудит нашёл пять потоков работы,
существовавших только вне git, — цена нарушения этого правила.
