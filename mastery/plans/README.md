# plans — реестр планов

Единый учёт планов по аналогии с трекером: реестр `registry.csv`, ключ `PLAN-<id>`
(автоинкремент, не переиспользуется).

## Что считается планом

План — **пошаговый документ, по которому исполняется работа**: этапы, шаги, гейты.
Не путать:

| Документ | Отвечает на | Живёт |
|---|---|---|
| План | «как именно делаем, какими шагами» | здесь или в домене, зарегистрирован в реестре |
| Диздок | «что и почему строим, что подписать» | `design_docs/` |
| STATUS домена | «где мы сейчас» | домен |

## Правила

1. **Каждый живой план зарегистрирован** в `registry.csv`. Незарегистрированный
   план — черновик, на него нельзя ссылаться как на план работ.
2. **Доменные `PLAN.md` остаются в доменах** (правило «цифра рождается в домене»),
   реестр ссылается на них колонкой `файл`. Новые планы конкретных работ,
   не привязанные к одному домену или слишком узкие для доменного PLAN.md,
   кладутся сюда: `mastery/plans/PLAN-<id>_<slug>.md`.
3. **План привязан к задаче трекера** (`задача_трекера`), если он исполняемый.
   Обзорные планы направлений могут жить без задачи.
4. Статусы: `черновик` → `утверждён, ждёт исполнения` → `выполняется` →
   `выполнен` / `устарел`. Устаревший план не удаляется — помечается.
5. Этапы исполняемого плана соотносятся со статус-тегами задачи — по ним же
   срабатывают триггеры `mastery/registry.csv`.

## Схема registry.csv

`ключ, название, домен, задача_трекера, статус, файл, создано, обновлено`
