# Выбор хеш-функции для сравнения строк (PG/GP)

Популярные варианты дают **молчаливые** дефекты: запрос не падает, хеши считаются,
строки просто не обновляются. Проверь всё ниже **до тиража**, на реальной ширине
самой широкой таблицы, а не на трёх колонках. Дефолт:

```sql
MD5(ROW(s.col_a::TEXT, s.col_b::TEXT, ...)::TEXT) AS row_hash
```

`ROW` — конструктор кортежа, а не вызов функции: лимит аргументов на него не
распространяется. Печатается с разделителями и экранированием, поэтому границы
полей однозначны, а NULL отличается и от пустой строки, и от строки `'NULL'`.

## Проверки до тиража

Каждая — однострочник, выполняется как есть. Ожидаемый ответ указан.

### 1. Лимит аргументов (на самой широкой таблице)

```sql
SELECT MD5(CONCAT_WS('|', 1,2,3, /* ...до реального числа колонок... */ 118));
```

Ожидание: на 100+ аргументах → `ERROR: cannot pass more than 100 arguments to a function`.
Граница проверена: 99 колонок + разделитель = 100 аргументов проходит, 100 колонок падает.
Почему важно: на `write_off_non_cash_funds_erp` (118 колонок) это выстрелило **в рантайме**,
а не на ревью — на других таблицах шаблон работал. Ширина таблицы не видна в диффе SQL,
поэтому ревьюер такое не ловит. Страж ширины до генерации:

```sql
SELECT table_name, COUNT(*) AS cols FROM information_schema.columns WHERE table_schema='stg' GROUP BY 1 HAVING COUNT(*) >= 99 ORDER BY 2 DESC;
```

### 2. Поведение на NULL

```sql
SELECT MD5(CONCAT_WS('|',NULL,'Москва')) = MD5(CONCAT_WS('|','Москва',NULL)) AS concat_ws_collision, MD5(ROW(NULL,'Москва')::TEXT) = MD5(ROW('Москва',NULL)::TEXT) AS row_collision;
```

Ожидание: `concat_ws_collision = t`, `row_collision = f`. Почему важно: `CONCAT_WS` **молча пропускает** NULL-аргументы, а не оставляет пустую
позицию. Перестановка значения между двумя nullable-колонками даёт **одинаковый**
хеш — строка считается неизменённой и не обновляется: тихая потеря данных, а не
ошибка. Дефект найден **уже в смерженной волне 1** и потребовал перегенерации всей
волны. Тот же класс — `COALESCE(x,'NULL')`: реальное значение `'NULL'` в текстовой
колонке становится неотличимо от NULL. Убедись также, что NULL ≠ пустая строка:

```sql
SELECT ROW(NULL::TEXT,''::TEXT)::TEXT AS repr, MD5(ROW(NULL::TEXT,'x')::TEXT) = MD5(ROW(''::TEXT,'x')::TEXT) AS null_eq_empty;
```

Ожидание: `repr = (,"")`, `null_eq_empty = f`.

### 3. Различимость границ полей

```sql
SELECT MD5('ab'||'c') = MD5('a'||'bc') AS concat_collision, MD5(ROW('ab','c')::TEXT) = MD5(ROW('a','bc')::TEXT) AS row_collision;
```

Ожидание: `concat_collision = t`, `row_collision = f`. Почему важно: голая конкатенация `||` склеивает поля, сдвиг символа между соседними
колонками невидим. Для 1С-полей свободного текста (`comment`, `delivery_address`,
`additional_info`) границы реально плавают. Разделитель-константа не спасает: если он
встречается в данных, коллизия возвращается — `ROW` экранирует (`('a,b','c')` отличим).

### 4. Стабильность к размеру чанка

```sql
WITH v AS (SELECT ARRAY(SELECT i::TEXT FROM generate_series(1,120) i) AS a) SELECT MD5(MD5(array_to_string(a[1:90],''))||MD5(array_to_string(a[91:120],''))) = MD5(MD5(array_to_string(a[1:60],''))||MD5(array_to_string(a[61:120],''))) AS stable_across_chunking FROM v;
```

Ожидание: `stable_across_chunking = f` — вложенный хеш **нестабилен**. Почему важно: `MD5(MD5(chunk1), MD5(chunk2), ...)` — типовой обход лимита в 100
аргументов, отвергнут осознанно. Результат привязан к размеру чанка: при чанке 90 и
60 хеши разные. Правка генератора, добавление колонки или смена размера чанка меняют
хеш **всех** строк — молчаливый перепрогон backfill всей таблицы, а до него все строки
выглядят изменёнными. Требование: хеш зависит от значений и порядка колонок, но не
от того, как их разбили при вычислении.

### 5. Совпадение множества колонок

```sql
SELECT COUNT(*) AS null_hash FROM ods.<table> WHERE row_hash IS NULL;
```

Ожидание: `0` после backfill, **до** мержа SQL. Обратный порядок (SQL раньше backfill)
гарантированно даёт полный дубль таблицы — воспроизведено: 100k → 110k. Список колонок
в `INSERT`, `SELECT` и внутри хеша обязан совпадать посимвольно: `sqlfluff` проверяет
форматирование, а не множества — расхождение ловит только инвариант верификатора.

## Оговорки к MD5(ROW(...)::TEXT)

Приведение кортежа к `TEXT` — **текстовое представление**, зависящее от настроек сессии
и типов. Рекомендацию не отменяет, но требует дисциплины.

**1. DateStyle.** `ROW('2026-08-20'::DATE)::TEXT` даёт `(2026-08-20)` при `ISO, DMY`
и `(20/08/2026)` при `SQL, DMY` — **разные хеши**:

```sql
SET DateStyle='ISO, DMY'; SELECT MD5(ROW('2026-08-20'::DATE)::TEXT); SET DateStyle='SQL, DMY'; SELECT MD5(ROW('2026-08-20'::DATE)::TEXT); RESET DateStyle;
```

Зафиксируй `DateStyle` (и `IntervalStyle`, `TimeZone` при timestamptz) на уровне БД/роли
Airflow либо приводи даты явно `TO_CHAR(d,'YYYY-MM-DD')` — иначе backfill из одной сессии
и инкремент из другой разойдутся молча.

**2. Типозависимость представления.** `1::NUMERIC` и `1.0::NUMERIC` дают **разные**
хеши (печатается масштаб), а `1::INT` и `'1'::TEXT` — одинаковые:

```sql
SELECT MD5(ROW(1::NUMERIC)::TEXT)=MD5(ROW(1.0::NUMERIC)::TEXT) AS numeric_scale_same, MD5(ROW(1::INT)::TEXT)=MD5(ROW('1'::TEXT)::TEXT) AS int_eq_text;
```

Следствие: смена типа колонки в DDL меняет хеш всей таблицы. Приводи каждую колонку
к `::TEXT` явно и одинаково в backfill и в инкременте.

**3. Порядок колонок** входит в хеш: смена порядка = перепрогон backfill.

## Анти-паттерны

- `CONCAT_WS(sep, <много колонок>)` — лимит 100 аргументов + молчаливый пропуск NULL.
- `col_a || col_b || ...` без разделителя — склейка границ; с `COALESCE(x,'NULL')` ещё и путает NULL со строкой `'NULL'`.
- `MD5(MD5(chunk1) || MD5(chunk2) || ...)` — привязка к разбивке, молчаливый перепрогон backfill.
- Разный список/порядок колонок в backfill и в инкрементальном SQL — вечно «изменённые» строки.
- Разное выражение хеша на разных таблицах одной волны — сравнивать между собой уже нельзя.
- `=` вместо `IS NOT DISTINCT FROM` по ключу при nullable-ключе — меняет семантику; проверь `COUNT(*) WHERE <ключ> IS NULL = 0`.
- Проверка «работает» на трёх колонках вместо реальной ширины — лимит и NULL-дефект так не видны.
