# Исполнитель делегированного тикета

Делегирование — это не «прочитал название и побежал». Тикет — вершина графа:
у него есть описание, DoD, связи и история обсуждения, а вокруг — правила
директории. Исполнитель, который берёт только заголовок, делает чужую
задачу вместо поставленной.

## Протокол — по шагам, порядок обязателен

### 1. Собрать контекст ДО работы

Прочитать полностью, не выборочно:

- **строку тикета** в `mastery/tracker/tasks.csv`: описание, DoD, статус,
  автора; DoD — это критерий завершения, а не пожелание;
- **связи** в `links.csv` — в обе стороны (обратные выводятся: `блокирует`,
  прочитанный задом наперёд); родительский epic/проект даёт рамку;
- **комментарии** `comments/<КЛЮЧ>.md` — там решения и грабли прошлых
  подходов; повторить отвергнутый путь = не прочитал;
- **`AGENTS.md`** — правила директории: журнал, локи, домены, витрины;
- **`mastery/registry.csv`** — триггеры для статуса и домена тикета:
  сработавшие скиллы читать до работы (§4 AGENTS.md).

### 2. Проверить блокеры

Есть открытое ребро `X блокирует <КЛЮЧ>` с незакрытым X → **не начинать**.
Записать комментарий «взял, но заблокирован X», финал — `РЕЗУЛЬТАТ: нужно
решение`. Начатая работа под блокером — выброшенная работа.

### 3. Взять в работу видимо

Статус тикета → `разработка` (правка CSV — под локом `ctx_lock.py`,
`обновлено` — свежим временем). Смена статуса включает триггеры реестра.

### 4. Работать до DoD, артефактами

- Каждый пункт DoD закрывается файлом-артефактом или проверяемым фактом
  (rule-1: артефакт или не было).
- Артефакты — в домен тикета; тяжёлое генерируемое — в `generated/`.
- Открылась подзадача не из DoD — не расползаться: строка в комментарий,
  предложение нового тикета в финальном ответе.

### 5. Записать ход в тикет

Комментарий в `comments/<КЛЮЧ>.md` (секция `## агент · дата`): что сделано,
что выяснилось, где спотыкался. Чат прокручивается — комментарий остаётся.

### 6. Финал — честный статус и маркер

- DoD выполнен → статус `ревью` (**не** `закрыт`: закрывает владелец после
  просмотра), комментарий со сводкой.
- Упёрся в выбор, который вправе сделать только человек → статус не трогать
  дальше `разработка`, вопрос — в комментарий.
- Строка в `work_journal.md` (append-only, под локом) и строка применения
  этого скилла в `usage_log.csv`.
- **Последняя строка ответа — машинный маркер**, ровно один:

```
РЕЗУЛЬТАТ: готово
РЕЗУЛЬТАТ: нужно решение: <вопрос одной строкой>
РЕЗУЛЬТАТ: блокер: <что мешает, одной строкой>
```

По маркеру обвязка (`bin/delegate`) шлёт человеку нотификацию: «готово» —
можно смотреть ревью; «нужно решение»/«блокер» — требуется внимание.
Ответ без маркера обвязка трактует как «нужно решение» — молчание не
считается успехом.

## Анти-паттерны

| Симптом | Чем кончается |
|---|---|
| взял по заголовку, DoD не читал | сделана соседняя задача |
| не посмотрел комментарии | повторён отвергнутый подход |
| закрыл сам в `закрыт` | ревью пропущено, резолюция пустая |
| «почти готово» без маркера | человек не позван, задача повисла |
| работа под открытым блокером | результат выброшен после решения блокера |

Ключ реестра: MST-33

Журнал применений: mastery/usage_log.csv — после каждого применения добавь строку
(`дата,скилл,кто,задача,исход,заметка`; исход: `помог|частично|не_помог|вреден`;
писать под локом `ctx_lock.py`) — см. AGENTS.md §4.
