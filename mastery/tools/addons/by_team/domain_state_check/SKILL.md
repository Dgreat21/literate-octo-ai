# Сверка с фактическим состоянием домена перед записью

Между чтением домена и записью проходит время, и домен за это время живёт: агент
занял номер, файл переехал, схема CSV выросла, задача закрылась. Черновик на
двухчасовом снимке выглядит уверенно и потому опасен: читатель не отличит
устаревшее допущение от факта, а документ зафиксирует его как истину.

**Правило: снимок домена в твоей голове недействителен. Перед записью — перечитай.**

## Что сверять

### 1. Фактическое дерево домена — `ls` / `glob`, не по памяти

Выполни `ls <домен>/` и `ls` по затронутым подпапкам. Путь не пиши по памяти
и не переноси из черновика.

> Реальный случай (журнал, 2026-08-20 22:47): в свежесозданном файле стояла
> ссылка на `team/` в корне `.context/`, тогда как `team/` давно переехал
> в `mastery/team/` (§1 AGENTS.md). Ссылка выглядела правдоподобно и была битой.

### 2. Занятые номера — `grep` по ВСЕМУ домену, не по одному файлу

Ищи так, чтобы увидеть весь диапазон сразу, а не первое совпадение:

```bash
grep -rhno "DC-[0-9]\+" datacatalog/ .other/ | sort -u   # заняты
```

Проверяй все места нумерации: домен, `.other/`, трекер, реестр, журнал. Номер,
«выведенный из обращения», занят навсегда — переиспользование ломает ссылки.

> Реальный случай (22:47): `DC-10` выписали новой развилке, хотя номер уже был
> занят развилкой про porcelain — смотрели один файл, а не домен. Позже (23:10)
> `DC-10..DC-12` выведены из обращения при переезде в `.other/dc_enrichments/`
> как `E-01..E-03`, следующий номер ядра — `DC-13`: помнящий «дальше DC-10»
> ошибётся дважды.

### 3. Актуальная схема CSV — прочитай заголовок, не предполагай

Прочитай **первую строку файла** и построй ряд под неё, посчитав колонки.
Проверь также, не появилось ли рядом новых файлов схемы.

```bash
head -1 mastery/tracker/tasks.csv; ls mastery/tracker/
```

> Реальный случай (23:10): схема трекера поменялась **прямо во время работы** —
> стала 13 колонок, рядом появились `links.csv` (рёбра вынесены из строки)
> и `comments/` (история обсуждения вынесена из ячейки). Ряд по прежней схеме
> встал бы со сдвигом колонок, а связи в старом поле потерялись бы молча.

### 4. `git log` домена с момента твоего последнего чтения

```bash
git -C .context log --oneline -15 -- <домен>/ mastery/tracker/
git -C .context status --short
```

Смотри не только на коммиты, но и на `git mv`: переезд папки не виден в черновике.

### 5. Статусы связанных задач в трекере

Прежде чем ссылаться на задачу как на открытую, зависящую или блокирующую —
прочитай её строку сейчас: `статус_тег`, `статус`, `резолюция_тег` и рёбра
в `links.csv`. Задача могла быть закрыта, заморожена или уведена на другой путь.

> Реальный случай (22:47): черновик опирался на развилку Р4 как на открытую —
> она была давно закрыта решением «`.context` — свой git». Вывод строился
> на несуществующей неопределённости.

## Быстрый порядок проверки (~2 минуты)

```bash
cd .context
ls <домен>/                                                  # 1. дерево
grep -rhno "<ПРЕФИКС>-[0-9]\+" <домен>/ .other/ | sort -u    # 2. номера
head -1 mastery/tracker/tasks.csv && ls mastery/tracker/     # 3. схема CSV
git log --oneline -15 -- <домен>/ mastery/ && git status -s  # 4. что уехало
grep -n "^<КЛЮЧ>," mastery/tracker/tasks.csv                 # 5. статусы
```

Пять команд — дешевле правки постфактум и тем более документа, на который
две недели ссылались как на верный.

## Признаки, что ты работаешь на устаревшем снимке

- Между чтением домена и записью ты сделал больше 3-4 шагов или сменил тему.
- Текст опирается на «как я уже видел», «в домене есть», «следующий номер».
- Путь или номер ты переносишь из черновика/плана, а не из вывода команды.
- Ты возвращаешься к задаче, отложенной вчера или в прошлой сессии.
- Домен параллельно трогает кто-то ещё (лок, чужая ветка, свежие коммиты).
- Ты берёшь «следующий свободный номер», не посмотрев список занятых.
- Ты пишешь ряд CSV по образцу соседней строки, а не по заголовку файла.

## Чек-лист перед записью

- [ ] `ls` по домену выполнен сейчас; все упоминаемые пути существуют.
- [ ] Занятые номера собраны `grep`-ом по домену + `.other/` + трекер + реестр.
- [ ] Новый номер больше максимального занятого; выведенные из обращения не переиспользованы.
- [ ] Заголовок целевого CSV прочитан; число полей в ряду равно числу колонок.
- [ ] Проверено, не появились ли рядом новые файлы схемы (`links.csv`, `comments/`).
- [ ] `git log` и `git status` по домену просмотрены; переезды (`git mv`) учтены.
- [ ] Статусы всех задач, на которые ссылаешься, прочитаны из трекера сейчас.
- [ ] Расхождения исправлены в тексте, а не «учтены в уме», и названы в журнале.

Нашёл расхождение — сначала правь черновик, потом пиши: документ, выпущенный
с известной ошибкой «поправим потом», не правится никогда.
