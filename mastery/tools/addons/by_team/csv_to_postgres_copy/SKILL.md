# CSV → Postgres через psql COPY

Загрузчик-образец: `~/.dsh-agent/sync_files.py` (синк реестров `.context` в БД
`agent`, схема `files`). Читай его перед тем, как писать свой.

## 1. Почему COPY text, а не альтернативы

| Вариант | Почему нет |
|---|---|
| psycopg / sqlalchemy | В системном Python драйвера нет. Тянуть зависимость ради 250 строк несоразмерно. `psql` уже стоит (`/opt/homebrew/opt/libpq/bin`) и им пользуются соседние скрипты. |
| Пачка `INSERT` | N раундтрипов вместо одного потока; кавычки в значениях надо экранировать всё равно, но ошибка даёт не сбой, а SQL-инъекцию. |
| `COPY ... FORMAT csv` | Внутри `psql` поток идёт через stdin, где терминатор `\.` действует всё равно, а csv-формат добавляет вторую систему правил (кавычки, удвоение кавычек, `QUOTE`/`ESCAPE`) поверх первой. Text-формат — один набор правил, полностью в твоих руках. |

Транспорт всегда один: `psql -v ON_ERROR_STOP=1`, скрипт подаётся на stdin
целиком — `BEGIN; TRUNCATE …; COPY … FROM STDIN; <данные> \. COMMIT;`.
`TRUNCATE` и `COPY` в ОДНОЙ транзакции: упавший `COPY` откатит `TRUNCATE`,
и витрина не останется пустой (корневой `AGENTS.md` §9.3).

## 2. Экранирование text-формата — таблица

Применяй ровно в этом порядке, обратный слеш ПЕРВЫМ:

| Символ в значении | Пишем в поток | Что будет, если забыть |
|---|---|---|
| `\` (обратный слеш) | `\\` | съест следующий символ, значение поедет |
| таб | `\t` | лишняя колонка → `extra data after last expected column` |
| перевод строки `\n` | `\n` | лишняя СТРОКА → сдвиг всей таблицы (самая вероятная тихая поломка на многострочных описаниях) |
| возврат каретки `\r` | `\r` | хвостовой `\r` в значении, CRLF-файлы ломаются молча |
| NULL | `\N` | пустое значение приедет как пустой текст, а не NULL |
| одиночная `.` в начале строки | `\.` | **`\.` — терминатор COPY в psql stdin**: остаток данных уедет парсеру SQL, ошибка будет невнятной и далеко от причины |

```python
NULL_MARK = "\\N"

def cell(value) -> str:
    if value is None or value == "":
        return NULL_MARK
    return (str(value).replace("\\", "\\\\")
                      .replace("\t", "\\t")
                      .replace("\n", "\\n")
                      .replace("\r", "\\r"))
```

Замена `\` → `\\` покрывает и точку: строка `.` превращается в `\.` только
если она пришла как литерал `\.`; одиночную `.` защищай тем, что поле никогда
не начинается со строки данных — она всегда идёт после таба или является
первой колонкой, поэтому ЯВНО проверь этот кейс тестом (§4), а не рассуждением.

Пустая строка CSV = NULL, а не `""`. Держи одну трактовку на весь проект:
расхождение между двумя загрузчиками в одном репозитории дороже, чем кажется.

## 3. Направление синка

**Файл — истина, БД — производная витрина.** Синк ТОЛЬКО односторонний,
CSV → БД. Следствия, которые обязан соблюсти:

- файлы открываются строго на чтение, скрипт в них не пишет НИКОГДА;
- блокировки (`ctx_lock.py`) не нужны — писателя нет;
- правки в БД бессмысленны: следующий прогон их перезатрёт, скажи это в
  докстринге скрипта, чтобы никто не «починил» данные в таблице.

Зачем БД вообще: «какие задачи входят в PRJ-1 и сколько у них комментариев» в
CSV требует парсера JSON в каждой ячейке, в SQL это один запрос.

## 4. Обязательный тест на злых значениях

Без него загрузчик не считается сделанным. Засей строку, где в ОДНОМ поле:

1. перевод строки, 2. таб, 3. обратный слеш `\`, 4. одиночная точка `.` в
начале строки, 5. одинарная и двойная кавычки, 6. юникод (кириллица, эмодзи),
7. пустая строка (→ NULL), 8. строка `\N` как литерал.

Затем **посимвольно сверь** выгруженное обратно с исходником — не «глазами»,
а сравнением: `python -c` с `assert db_value == file_value`, либо
`SELECT md5(поле)` против `md5` исходного значения. Совпадение длины
недостаточно. На реальном прогоне так сверялись 100 полей трекера — 0 расхождений.

## 5. Идемпотентность по sha256

Считай `sha256` файла и храни его в таблице-реестре (`files.registry`).
Прогон пропускает файл, если хеш совпал; `--force` игнорирует хеши.
Для каталога (много `.md` на одну таблицу) хеш считай от **имён и содержимого**
всех файлов по порядку — иначе удаление файла не будет считаться изменением.
Каталог грузи целиком одним `COPY`: `TRUNCATE` затрёт пофайловую загрузку.

## 6. Поведение при битом входе

Останавливайся. Проверяй JSON/типы ДО формирования потока и падай с сообщением,
называющим **файл, строку (бизнес-ключ) и поле**:

```
mastery/tracker/tasks.csv: строка MST-21, поле «комментарии» —
невалидный JSON (…). Проверьте CSV, синк остановлен.
```

Частичная загрузка запрещена: битый JSON в ячейке не должен стать валидным
JSONB — мусор всплывёт запросом через неделю. Ошибку пиши и в реестр
(`parse_error`), файл помечай как незагруженный, общий статус прогона `partial`.
Осторожно со строителями сообщений: `Path.relative_to` бросает `ValueError` на
пути вне workspace и подменяет внятную причину невнятной — заворачивай в хелпер.

## 7. Вложенные структуры

- Списки объектов (комментарии, связи) → **JSONB**: в поток отдаётся сырой
  валидированный текст JSON, пустое → `[]`.
- Плоские перечисления через `;` → **TEXT[]**: `{"a","b"}`, внутренние кавычки
  экранируются `\"`, пустое → `{}`.
- Дубли по PRIMARY KEY отсеивай в Python (`seen: set`) — `COPY` упадёт на них
  целиком, а не на строке.

## 8. Анти-паттерны

- `TRUNCATE` и `COPY` отдельными вызовами `psql` → пустая витрина при сбое.
- `psql` без `-v ON_ERROR_STOP=1` → ошибка проглатывается, код возврата 0.
- Игнорировать `returncode`/`stderr` `subprocess.run` → «загрузилось» при пустой таблице.
- Читать CSV без `encoding="utf-8-sig"` → BOM въезжает в первое имя колонки.
- `f"'{value}'"` для SQL-строк реестра вместо `replace("'", "''")` → инъекция.
- Двусторонний синк «БД first, файл dump» → две копии всегда расходятся.
- Судить о загрузке по `n_live_tup` → без `ANALYZE` там нули, вывод «база пустая» ложный.

## 9. Чек-лист

- [ ] Транспорт: `psql -v ON_ERROR_STOP=1`, скрипт целиком на stdin.
- [ ] `BEGIN; TRUNCATE; COPY … FROM STDIN; \. COMMIT;` в одной транзакции.
- [ ] `cell()` экранирует `\` первым, затем таб/`\n`/`\r`; NULL → `\N`.
- [ ] Проверен кейс одиночной `.` в начале строки.
- [ ] Пустая строка CSV трактуется как NULL — так же, как в соседних загрузчиках.
- [ ] Тест на злых значениях прогнан, сверка посимвольная.
- [ ] `sha256` файла/каталога в реестре, есть `--force` и `--dry-run`.
- [ ] Битый вход останавливает синк с указанием файла/строки/поля.
- [ ] Файлы открываются только на чтение; направление синка описано в докстринге.
- [ ] `returncode` каждого вызова `psql` проверен, `stderr` попадает в сообщение.
