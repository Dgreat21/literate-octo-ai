# Mermaid из данных, а не из головы

Диаграмма, нарисованная руками, протухает на второй правке статуса и начинает
врать. Диаграмма, сгенерированная из источника истины, разойтись с ним не может
по построению. Это единственная причина, по которой стоит писать генератор
вместо того, чтобы один раз нарисовать картинку.

## Правило 1: источник — данные, а не текст диаграммы

Плохо: положить в репозиторий `.md` с готовым `flowchart`, где узлы вбиты
руками. Через неделю статусы поменяются, а картинка нет.

Хорошо: функция `graph()` читает `links.csv` и `tasks.csv` и собирает
`flowchart` каждый раз заново. Диаграмма всегда показывает то, что есть
в файлах на этот момент.

Практический признак, что вы делаете правильно: **у диаграммы нет своего
файла с содержимым** — только код, который её собирает.

## Правило 2: «сгенерировал» ≠ «рисуется»

Генератор выдаёт текст. Текст может быть синтаксически невалидным, и вы
об этом не узнаете, пока не отрендерите. Проверка «строка начинается
с `flowchart`» не доказывает ничего.

Прогон через настоящий mermaid — обязателен:

```bash
# headless Chrome + локальный mermaid.min.js
mermaid.render('id', code)  # ловим исключение
```

На этом было поймано **семь реальных ловушек**, каждая из которых выглядела
как рабочий код:

1. **`sankey-beta` не парсится** в 11.17, хотя встречается в старой
   документации. Нужно `sankey`.
2. **Круглые скобки внутри `id[...]` роняют весь kanban.** Не одну карточку —
   всю доску. Название «Закрыть развилки DC-01 (схема FQN)» ломало экран.
3. **`eventmodeling` не принимает кириллицу в идентификаторах.**
   `tf 01 ui ДашбордНаИнстансе` → `Lexer error: unexpected character`.
   Подписи кириллицей в инлайн-данных `{ … }` при этом проходят — ограничение
   только на идентификатор сущности. Проверено рендером 11.17.
4. **Дорожки `eventmodeling` — `ui`, `cmd`, `evt`, `rmo`, `pcr`.**
   Напрашивающиеся по смыслу `view` и `proc` парсер отвергает
   (`Expecting end of file`). Отдельный токен `rf` (= `resetframe`) —
   валиден, не примите его за опечатку `tf`.
5. **`class X имя` в stateDiagram не принимает кириллицу в id состояния.**
   `class Синхронизирован ok` → `Lexical error`. Лечится алиасом:
   `state "Синхронизирован" as Synced` плюс `class Synced ok` — подпись
   остаётся русской, id латинский. `classDef` при этом ставится ПОСЛЕ
   объявления состояний.
6. **Проверять надо не «отрендерилось», а «цвет доехал».** Диаграмма со
   стилями и без рендерятся одинаково успешно, а у C4 совпала даже длина SVG.
   Негативный контроль: искать hex в готовом SVG и убедиться, что без стилей
   его там НЕТ.
7. **Sankey не принимает кириллицу вообще.** Падает даже на `А,Б,5`.
   Кавычки не спасают. Лечится переводом/транслитерацией подписей.
6. **`timeline` не падает на мусоре — и это опаснее падения.** Строка без
   разделителя ` : ` не отвергается, а молча рисуется как период без событий:
   `@@@ ??? !!!` и `просто текст` дают валидный SVG на 11 КБ. Проверка
   «отрендерилось без исключения» здесь не доказывает ничего. Считайте
   **подписи в SVG**: у валидной timeline их 2 на событие (период + текст),
   у проглоченного мусора — 1 на строку. Проверено рендером 11.17.

## Как рендерить, если headless Chrome не запускается

`mermaid.parse()` в node — **не замена рендеру**: для `timeline` он пропускает
даже заведомый мусор (см. ловушку 6), а `title`/`section` роняет на отсутствии
DOMPurify, то есть даёт ложные FAIL. Оба класса ошибок — в разные стороны.

Если системный Chrome не поднимается (в песочнице — отказ crashpad на правах),
рабочий путь — puppeteer со своим Chrome:

```js
const puppeteer = require('<путь>/node_modules/puppeteer');
const b = await puppeteer.launch({headless:'new', args:['--no-sandbox']});
const p = await b.newPage(); await p.setContent('<html><body></body></html>');
await p.addScriptTag({path: '<...>/static/mermaid.min.js'});
await p.evaluate(() => mermaid.initialize({startOnLoad:false}));
// mermaid.render(id, code) внутри p.evaluate — настоящий DOM, настоящий рендер
```

Контроль исправности харнесса: заведомо битый тип (`timelineXXX`) и битый
`erDiagram` обязаны **падать**. Если «проходит всё» — сломан прогон, а не данные.

## Правило 3: экранируй всё, что пришло из данных

Названия задач содержат кавычки, скобки, `-->`, `#`. Любой из этих символов
рвёт не подпись, а диаграмму целиком: mermaid не умеет «пропустить плохой
узел».

Минимальный набор замен для подписи:

| Символ | Чем плох | Замена |
|---|---|---|
| `"` | рвёт строковый литерал | `'` |
| `[` `]` | границы узла | `(` `)` |
| `{` `}` | границы узла другой формы | `(` `)` |
| `#` | начало HTML-entity | `№` |
| `-->` | рвёт ребро пополам | `→` |
| перевод строки | рвёт инструкцию | пробел |

**Внимание:** у разных типов диаграмм строгость разная. `flowchart` терпит
круглые скобки в подписи, `kanban` — нет. Универсального экранирования
не существует: пишите функцию под тип, если общая не подошла.

## Правило 4: защищайся от циклов в данных

Связи задач образуют граф, а в графе бывают циклы: `A входит в B входит в A`.
Наивный обход уйдёт в бесконечную рекурсию и повесит весь UI. Данные кривые —
это правда, но падать из-за них приложение не должно.

Всегда носите с собой `seen: set` и ограничение глубины.

## Правило 5: сверяйся с reference, а не с памятью

Синтаксис новых типов (`ishikawa`, `treeView`, `wardley`, `cynefin`,
`eventmodeling`) меняется от версии к версии и плохо угадывается. В
`mastery/tools/addons/source/WH-2099/mermaid-skill/.claude/skills/mermaid/references/`
лежит по файлу на тип — 37 штук. Открыть нужный дешевле, чем отлаживать
`Parse error`.

Ровно так были починены три моих ошибки в синтаксисе: я писал по памяти,
reference показывал правильную форму.

## Какой тип под какую задачу

| Что показываем | Тип | Почему он |
|---|---|---|
| зависимости задач | `flowchart` | стрелки с подписями, кликабельные узлы |
| состав эпика | `mindmap` | дерево без ручной раскладки |
| цель → проект → веха | `treeView` | компактнее mindmap на глубине 4 |
| где скапливается работа | `sankey` | толщина потока = количество |
| доска | `kanban` | нативный тип, не надо верстать |
| сроки спринтов | `gantt` | даты из данных |
| разбор инцидента | `ishikawa` | причины по категориям |
| ветки и мержи | `gitgraph` | единственный тип про git |
| контуры системы | `architecture` | группы и сервисы |
| поток работы | `eventmodeling` | разделяет команду, событие и чтение |

## Чек-лист перед «готово»

- [ ] Диаграмма собирается из источника истины, а не лежит текстом.
- [ ] Прогнана через настоящий рендер, а не проверена глазами.
- [ ] Подписи экранированы; проверено на названии со скобками и кавычками.
- [ ] Обход защищён от циклов (`seen` + предел глубины).
- [ ] Синтаксис сверен с reference-файлом соответствующего типа.
- [ ] Если тип не принимает кириллицу — подписи переведены осмысленно,
      а не транслитерированы механически (`Done` читается, `zakryt` — нет).
