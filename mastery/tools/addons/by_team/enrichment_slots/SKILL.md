# Слоты обогащения

Цель — сделать исчезновение части объёма **штатным режимом**, а не аварией.
Механизм переиспользуем: каталог, витрина, интеграция, набор отчётов.

## 1. Раздели на два уровня

- **Ядро** — то, что обязано работать всегда: собирается из своего репозитория,
  ни от кого не зависит, продано/согласовано.
- **Обогащения** — всё остальное: непроданное, чужое, недосогласованное,
  зависящее от внешнего гранта.

> **Главное правило: ядро обязано собираться при нуле подключённых обогащений.**
> Отсутствие обогащения не ломает сборку, не роняет CI, не оставляет битых ссылок.

## 2. Заведи слоты — до появления поставщиков

Слот — **именованное необязательное поле** с описанной семантикой. Ядро знает
имя слота и что в нём лежит; **кто заполнит — не знает**.

Слот заводится **до** поставщика: сначала контракт, потом реализация. Обратный
порядок = контракт подогнан под конкретный инструмент, второй поставщик не влезет.

### Обязательный артефакт: таблица «слот → деградация без него»

Без колонки «деградация» слоты — украшение. Она заставляет назвать цену вслух.

| Слот | Что добавляет | Кто потребляет | Деградация без него |
|---|---|---|---|
| `business_key` | Бизнес-ключ таблицы | Docs v2, T1.2 | Поле пустое, показывается только ключ дистрибуции из DDL |
| `bi_usage` | Фактические обращения к таблицам | T2.6, T5.4 | Детект «мёртвых» витрин **отсутствует**, а не деградирует |
| `quality_tags` | Теги качества загрузки | T3.1 | Страница таблицы без секции качества |

Формулируй деградацию как наблюдаемый факт («поле пустое», «секции нет»),
а не «будет чуть хуже».

## 3. Правила R1–R6 (с «почему»)

| # | Правило | Зачем |
|---|---|---|
| **R1** | Ядро собирается при нуле провайдеров | Сборка без обогащений — режим по умолчанию, а не аварийный |
| **R2** | **Ссылки только в одну сторону.** Ни один файл ядра не упоминает конкретное обогащение | Удаление обогащения не оставляет битых ссылок |
| **R3** | Слот описан контрактом (поля, семантика), а не реализацией | Второй поставщик в тот же слот не требует переделки ядра |
| **R4** | У каждого заполненного слота обязателен `provenance` | Видно **в данных**, чем заполнено; отключение заметно без чтения кода |
| **R5** | У обогащений своё пространство нумерации решений/задач | Возврат материала не ломает нумерацию ядра, и наоборот |
| **R6** | В трекере связь только «обогащение блокируется ядром», никогда наоборот | Задача ядра никогда не ждёт непроданного или чужого |

**R2 — самое важное и единственное, что нарушается незаметно.** Именно оно
превращает отключение из рефакторинга в удаление папки. Нарушение выглядит
безобидно («просто сослался на соседний документ») и вскрывается только когда
обогащение уезжает — то есть в худший момент.

## 4. Гейты — ручная дисциплина не работает

1. **Гейт пустой сборки.** Прогони генерацию артефакта без единого провайдера.
   Проходит валидацию схемы → R1 соблюдено.
2. **Гейт односторонних ссылок.** `grep` по ядру не находит упоминаний контуров
   обогащений и их имён. Плюс проверка битых ссылок (`mastery/tools/check_refs.py`).
   Пустой вывод — обязательное условие приёмки, а не пожелание.
3. **Гейт провенанса.** Каждое непустое значение в слоте несёт `provenance`.
   Нет провенанса → значение не принимается.

Гейты 1 и 3 ставь в CI вместе с генерацией; гейт 2 — в ревью и в CI.

## 5. Процедура: подключить / отключить

Симметрична намеренно — это одна процедура в разные стороны.

**Подключить:**
1. Убедись, что слот существует и контракт описан. Нет — сначала заведи слот.
2. Зарегистрируй поставщика в конфигурации.
3. Перенеси материал в домен или в код.
4. Перенумеруй решения в пространство ядра, оставив ссылку на исходный номер.
5. Восстанови связи в трекере, разморозь задачи.
6. Прогони гейты §4. Событие — в `work_journal.md`.

**Отключить:**
1. Сними регистрацию поставщика.
2. Вынеси материал в свой контур (`git mv`, не копирование).
3. **Выведи номера решений из обращения — не переиспользуй.** Освободившийся
   номер, отданный новой теме, делает историю нечитаемой: ссылка из старого
   документа молча начинает указывать на другой предмет.
4. Сними кросс-связи в трекере, заморозь задачи.
5. Прогони гейты §4 — **особенно пустую сборку и битые ссылки**.
6. Зафиксируй, **что именно деградировало** и какова цена. Если цена есть —
   назови её явно, не растворяй.

## 6. Пример развязки: DC-10..12 → E-01..03

Обогащения каталога данных (`porcelain`, `optimisation`) оказались непроданы.
Что сделано:

- В ядре создан `datacatalog/ENRICHMENT_SLOTS.md`: 5 слотов с деградацией,
  правила R1–R6, процедура. **Поставщики в нём не названы** — это и есть R2.
- Материал вынесен в `.other/dc_enrichments/` с `project.md` (статус «не продано»,
  ссылки только в сторону ядра).
- Решения перенумерованы в своё пространство: `DC-10 → E-01`, `DC-11 → E-02`,
  `DC-12 → E-03`. Номера `DC-10..DC-12` в ядре **выведены из обращения**,
  следующая развилка ядра — `DC-13`.
- Из ядра вырезаны 3 строки таблицы, 3 секции `DECISIONS`, упоминания доменов
  в `README` и `PLAN`. Гейт R2: `grep` по `datacatalog/` пуст.
- Трекер: сняты рёбра `PORCELAIN-3 → DATACATALOG-3` и `OPTIMISATION-1 →
  DATACATALOG-4`, задача ядра возвращена на базовый путь (R6).
- **Цена названа вслух:** парковка `porcelain` убрала обход внешнего блокера,
  поэтому read-only грант на метабазу снова на критическом пути T0.1,
  а история BI-lineage тем временем не копится.

Последний пункт — обязательный. Слоты защищают **архитектуру** от связности,
а не **план** от потерь.

## 7. Анти-паттерны

- **Двусторонние ссылки.** Ядро сослалось на документ обогащения «для контекста».
  Отключение превращается в правку N файлов ядра — то есть в рефакторинг.
- **«Временный» импорт из надстройки в ядро.** Временного не бывает: он переживает
  автора. Если ядру что-то нужно — это принадлежит ядру, перенеси; иначе не бери.
- **Слот под конкретный инструмент.** Поля названы терминами поставщика — второй
  поставщик требует переделки контракта (нарушение R3).
- **Значение без provenance.** Через месяц никто не скажет, откуда цифра и что
  исчезнет при отключении.
- **Переиспользование освободившихся номеров.** Ссылка из истории начинает врать.
- **Деградация не названа.** «Будет чуть меньше данных» — а пропала целая функция.
- **Слот заведён после поставщика.** Контракт подогнан под реализацию.
- **Задача ядра блокируется задачей обогащения** (нарушение R6) — критический путь
  ядра начинает зависеть от непроданного.

## 8. Чек-лист

- [ ] Разделение «ядро / обогащения» проведено и записано.
- [ ] Есть таблица «слот → что добавляет → кто потребляет → деградация без него».
- [ ] Каждый слот описан контрактом, а не реализацией (R3).
- [ ] Ни один файл ядра не называет поставщика: `grep` пуст (R2).
- [ ] Прогнана пустая сборка — валидация проходит (R1).
- [ ] Каждое значение слота несёт `provenance` (R4).
- [ ] У обогащений своё пространство нумерации; старые номера выведены из
      обращения и не переиспользуются (R5).
- [ ] В трекере нет рёбер «ядро блокируется обогащением» (R6).
- [ ] Материал перенесён `git mv`, а не скопирован.
- [ ] Цена отключения (функциональная и временна́я) названа явно.
- [ ] Событие записано в `work_journal.md`.
