# tracker — задачи и цели в CSV

Текстовый таск-трекер: CSV-файлы, редактируются любым редактором, открываются
Excel, грепаются и парсятся. **Единственный источник истины** — копий по
доменам нет и не будет: две копии гарантированно разъедутся (rule-3).
Предметный срез по направлению даёт ключ-префикс:

```bash
grep "^DEMO-" tasks.csv                 # все задачи направления
python3 -c "import csv; [print(r['ключ'], r['статус_тег'], r['название']) \
  for r in csv.DictReader(open('tasks.csv')) if r['статус_тег'] != 'закрыт']"
```

В этом слепке лежит **demo-набор данных**; живые данные проекта вычищены.
Инструмент (веб-UI + ядро записи) выделен в пакет — сабмодуль
[`mastery/tools/saturday-tracker/`](../tools/saturday-tracker/), там же
полная документация по формату (`docs/DATA_FORMAT.md`) и архитектуре.

**Весь трекер одним взглядом:** [`OVERVIEW.md`](OVERVIEW.md) — генерируемый
снимок иерархии и статусов с инвариантами lineage.

## Файлы

| Файл | Что внутри | Ключи |
|---|---|---|
| `tasks.csv` | задачи: epic / story / task / bug | `<НАПРАВЛЕНИЕ>-<id>`, напр. `DEMO-1` |
| `goals.csv` | цели, проекты, вехи | `GOAL-<id>`, `PRJ-<id>`, `MS-<id>` |
| `links.csv` | связи между тикетами: ребро = строка | `откуда,тип,куда` |
| `sprints.csv` | спринты | `SPRINT-<id>` |
| `comments/<КЛЮЧ>.md` | обсуждение тикета, секция на реплику | файла нет = комментариев нет |

## Веб-UI

```bash
python3 -m saturday_tracker             # http://127.0.0.1:8777
```

Сервер на stdlib отдаёт собранный бандл и **живые данные** из файлов трекера.
Без БД: трекер открывается, даже когда Docker лежит. Слушает только localhost.
Карточка по прямой ссылке: `http://127.0.0.1:8777/t/DEMO-2` — такие ссылки
заменяют пересказ статуса в чате (`AGENTS.md` §5).

Что гарантирует запись — важно, потому что редактировать трекер можно
из двух мест сразу (UI и руками/агентом):

1. **Лок** `ctx_lock.py` — тот же мьютекс, что у агентов (`AGENTS.md` §8).
   Проверено: 5 одновременных правок разных тикетов, ни одна не потерялась.
2. **Атомарная запись** — во временный файл рядом + `os.replace` + `fsync`
   файла и каталога. Обрыв на середине не оставляет покорёженный CSV.
3. **`обновлено`** проставляется автоматически при любой правке, включая
   добавление комментария.
4. **git-коммит на каждую правку** — история «кто/когда/что» и откат любой
   правки: `git revert <хеш>`.

Ошибка на любом шаге показывается человеку. «Сохранилось, но нет» — исход,
которого здесь быть не может. После любой записи фронт **перечитывает CSV** —
показывает то, что в файлах, а не то, что предположил.

Иерархия: **цель** перетекает в **проекты**, проект разделяется на **вехи** и
**задачи**. Задача привязывается к проекту/вехе строкой в `links.csv`.

## Почему связи и комментарии — не колонки CSV

Раньше они лежали JSON-ом внутри ячейки. Три беды, все проверены на живых
данных перед миграцией:

1. **Дифф был нечитаем:** добавление одной реплики переписывало строку задачи
   целиком, git показывал изменение всего файла (`1,14c1,14`). Сейчас реплика —
   это `+4 строки` в своём файле, связь — `+1 строка` в `links.csv`.
2. **Связь дублировалась:** `A блокирует B` и `B блокируется A` — одно ребро,
   записанное дважды; из 22 связей одна пара успела разъехаться.
3. **Комментарий — проза**, а в JSON он нечитаем и правится только парсером.

`links.csv` хранит ребро **один раз**, в активной форме. Обратное направление
не хранится, а выводится при чтении: `блокируется` — это `блокирует`,
прочитанный задом наперёд. Поэтому рассинхрон исчез как класс, а не
отлавливается проверками.

## Правила

1. **Ключ** — `<НАПРАВЛЕНИЕ>-<id>`: направление капсом (= домен в контексте),
   id — автоинкремент внутри направления (max существующего + 1). Ключ не
   переиспользуется никогда, даже если задача удалена как ошибочная.
2. **Когда писать:** не каждый промпт, а когда есть понятная, выполнимая,
   атомарная задача. Мысли и черновики — в домен, в трекер — то, что можно
   взять в анализ.
3. **CSV append/edit:** новые задачи добавляются в конец; правка существующей
   строки разрешена (это не журнал), но `обновлено` меняется, а история
   решений — в `comments/<КЛЮЧ>.md`, не затиранием.
4. **Формат:** валидный CSV (RFC 4180, UTF-8 с BOM, разделитель `,`), только
   плоские скаляры, никакого JSON в ячейках. Комментарии — обычный Markdown.
5. **Связь пишется один раз.** В `links.csv` заносится активная форма
   (`блокирует`, `входит в`, `реализует`); обратную сторону не дублируем —
   читатель выводит её сам. Симметричные типы (`относится к`, `дублирует`)
   нормализованы по алфавиту ключей.

## Схема (tasks.csv и goals.csv одинаковые)

| Колонка | Что это |
|---|---|
| `ключ` | `<НАПРАВЛЕНИЕ>-<id>` / `GOAL-…` / `PRJ-…` / `MS-…` |
| `тип` | tasks: `epic` / `story` / `task` / `bug`; goals: `цель` / `проект` / `веха` |
| `название` | ну типо да |
| `автор` | имя владельца или `агент` |
| `согласовано` | `да` / `нет` — согласился ли пользователь с задачей |
| `статус_тег` | из словаря ниже |
| `статус` | лаконичное описание текущего положения своими словами |
| `описание` | контекст, достаточный чтобы взять задачу в анализ (ссылки на файлы доменов) |
| `dod` | пункты Definition of Done через `;` |
| `резолюция_тег` | `решен` / `не решен` — заполняется при закрытии |
| `резолюция` | post mortem: что вышло, что поняли |
| `создано` / `обновлено` | `YYYY-MM-DD HH:MM` |

Комментарии и связи в этих таблицах **не хранятся** — см. `comments/` и
`links.csv` выше.

### `comments/<КЛЮЧ>.md`

Заголовок файла — ключ тикета, дальше секция на реплику:

```markdown
# Комментарии: DEMO-1

## агент · 2026-08-20 00:55

реалистичный MVP за 2.5 дня: этап 0 целиком

## владелец · 2026-08-20 01:35

уточнил: к концу недели нужен именно диздок/план
```

Файла нет — значит комментариев нет. Пустых файлов не заводим.

### Словарь `статус_тег`

| Тег | Значение |
|---|---|
| `в беклоге` | задача не взята в работу или недостаточно описана |
| `анализ` | подтягивание контекста, разработка алгоритма решения, оценка рисков. Лечим не симптом, а причину. Здесь же выбирается **точка на спектре решений**: от «руками и безопасно» до «построить инструмент». Оба конца — абсолюты, правда посередине; этап анализа обязан этот спектр подсветить и выбрать точку осознанно |
| `планирование` | конкретные шаги до DoD, финальная сверка достижимости DoD; возможно заведение других задач под системные решения из анализа |
| `разработка` | создание/созидание решения, выполнение шагов плана |
| `тестирование` | тестирование исполнителем |
| `ревью` | на просмотре у автора/заказчика |
| `закрыт` | конец; `резолюция_тег` обязателен |

### Типы связей

В `links.csv` пишется **активная** форма:

| Тип | Направление | Обратное чтение |
|---|---|---|
| `блокирует` | `откуда` мешает `куда` начаться/закрыться | `куда` блокируется `откуда` |
| `входит в` | `откуда` — часть `куда` (задача → веха → проект → цель) | иерархия, обратного типа нет |
| `реализует` | `откуда` воплощает `куда` | иерархия, обратного типа нет |
| `относится к` | симметричный | тот же тип |
| `дублирует` | симметричный | тот же тип |

Связь пишется **один раз**. Пассивной формы `блокируется` в файле нет — это то
же ребро, прочитанное с другой стороны.
