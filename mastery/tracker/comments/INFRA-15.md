# Комментарии: INFRA-15

## агент · 2026-08-21 20:05

Разбирался с контрактом dsh по пакетам проверенной ревизии (`@deepseek-ai/dsh`
0.1.0-rc.7, `dsh-headless`, `dsh-base`, `dsh-llm-deepseek`, `dsh-tools`,
`deepseek-harness-sdk` 0.1.1rc1), а не по догадкам. Что выяснилось и что из
этого следует для бота:

1. **У headless нет сессий.** Его README прямо говорит: на каждую задачу
   создаётся свежий персистентный агент. Значит, кнопка «новая сессия» в
   прошлой версии бота была декорацией: `session_id` в cli-раннер вообще не
   передавался. Теперь бот об этом говорит вслух в карточке сессии.
2. **У headless нет и потока событий.** Из командной строки приложение
   принимает только текст задачи и `--help`; на stdout уходит последний
   ответ ассистента. Поэтому номер шага в cli-раннере честно не показывается —
   видно только время. Шаги есть в sdk-раннере: `on_notification` отдаёт
   события корневой сессии и потомков.
3. **Настройки существуют, но не флагами.** Усилие — `reasoningEffort`
   (`off|high|max`) ряда `llm-deepseek`, едет тем же `--patch`-оверлеем, что
   и модель. Права — `DSH_PERMISSION_MODE`
   (`read-only|workspace-write|danger-full-access`), пресеты ряда
   `permission` в dsh-base. Подача инструментов — `DSH_TOOLS_MODE`
   (`native|code|both`), это ближайший к «типу агента» рычаг в headless:
   пресеты агентов (`standard|code|minimal|cordis`) монтирует web-композиция,
   headless их не поднимает.
4. **Подтверждения в headless закрываются.** Политика `ask` без ответчика
   резолвится как `unavailable` и fail-closed. То есть прогоны с телефона
   молча не делают того, что требует подтверждения, пока режим прав не
   переключён осознанно.
5. **Провайдер по умолчанию был неверный.** В `TG_MODELS` стояло
   `deepseek/...`, а родной адаптер регистрирует маршрут `deepseek-official`;
   имя `deepseek` принадлежит каталогу pi-ai, который молчит без секции
   `llm-pi-ai` в settings. Умолчание исправлено.
6. **Проверка колбэков.** `allowed()` стоял только на сообщениях; инлайн-кнопки
   обрабатывались без проверки user_id. Теперь проверка на обоих входах.

Открытая развилка для владельца: раннер по умолчанию остаётся `cli`. Память
сессий и номера шагов даёт `sdk`, но его встроенная композиция ходит через
`bash-local` — без песочницы и подтверждений. Это не «включить галочку», а
решение про безопасность; когда решишь — заводим отдельную задачу на
cordis-композицию для бота (песочница + нужное усилие) и переключаем.
