# Herdr + DeepSeek Harness: сборка и удалённый доступ

Единственный источник истины по стеку (rule-3): установка, запуск, панели,
телефон. README домена только ссылается сюда.

## 1. Что в стеке

| Компонент | Роль |
|---|---|
| **Herdr** | терминальный мультиплексор для агентов: воркспейсы → табы → пейны, распознаёт агентов в пейнах, сайдбар со статусами, reattach с другой машины |
| **dsh** (DeepSeek Harness) | сам агент: `web`-профиль — браузерный UI на localhost, `headless` — одна задача → ответ → выход |
| **dsh-herdr** | обёртка headless-прогона: репортит `working/idle/blocked` в сайдбар Herdr через `pane report-agent` |
| **dsh_tg.py** | Telegram-бот: задачи dsh с телефона через long polling, несколько сессий в одном чате |

Проверенные версии: Herdr 0.8.2, dsh 0.1.0-rc.7, Node ≥ 24 (нужно ^22.19 или ≥24),
Python ≥ 3.11 (для бота — aiogram в venv).

### Апстримы — reference-сабмодули `agent-infra/vendor/`

Исходники обоих инструментов запинены на ревизии, против которых проверен
стек. Это референс для чтения, **не** дерево сборки: установка всё равно
идёт пакетным менеджером (`npx @deepseek-ai/dsh`, installer herdr.dev).

| Сабмодуль | Апстрим | Ревизия |
|---|---|---|
| `vendor/herdr` | github.com/herdrdev/herdr | тег `v0.8.2` |
| `vendor/deepseek-harness` | github.com/deepseek-ai/deepseek-harness | тег `dsh-v0.1.0-rc.7` |

Клонировать их не обязательно: `git submodule update --init
mastery/tools/saturday-tracker` подтянет только трекер; `--recursive`
притащит и vendor (herdr — тяжёлый, клонируй с `--depth 1`).

## 2. Запуск: `up.sh`

```bash
agent-infra/stack/up.sh            # весь стек
OCTO_DSH_PORT=3082 agent-infra/stack/up.sh   # свой порт web-панели
```

Что делает (идемпотентно):

1. проверяет Node (^22.19 || ≥24) и живой Herdr-сервер;
2. находит или создаёт Herdr-воркспейс с меткой `octo`
   (cwd = корень этого репозитория);
3. в корневом пейне поднимает `dsh web --port ${OCTO_DSH_PORT:-3081}` —
   **инстанс на проект**: вызывающая директория и есть воркспейс агента;
4. отдельный пейн под `dsh_tg.py`, если задан `TG_BOT_TOKEN`
   (иначе печатает, как его получить);
5. смоук: web-панель отвечает по HTTP, `herdr agent list` видит
   зарепорченные панели.

Порт по умолчанию **3081**, а не 3080: 3080 обычно занят web-инстансом
соседнего проекта. Правило то же — один проект, один инстанс, один порт.

## 3. Headless-задачи: `bin/dsh-herdr`

Одноразовая агентная задача «сделай и отчитайся»:

```bash
agent-infra/stack/bin/dsh-herdr "прогони линтер и перечисли ошибки"
dsh-herdr -C ~/proj -m deepseek/deepseek-v4-flash "суммаризируй git log за неделю"
```

- `-C <dir>` — рабочая директория задачи (по умолчанию текущая);
- `-m <provider/model>` — модель через `--patch`-оверлей профиля
  (headless сам по себе флага модели не имеет);
- внутри Herdr пейн репортится как агент `dsh` (`working` → `idle`/`blocked`),
  поэтому долгий прогон виден в сайдбаре, а `herdr agent list` непуст;
- вне Herdr — просто прогон без репортов, тот же контракт.

Допустимые статусы `pane report-agent`: `idle | working | blocked | unknown`.
Статуса `done` **нет** — завершение репортится как `idle` с `--message`.

## 4. Telegram-бот: `tg/dsh_tg.py`

Крутится на твоей машине, ходит в Telegram long polling'ом — входящие порты
и проброс наружу не нужны.

### Настройка (один раз)

1. `@BotFather` → `/newbot` → получи токен.
2. Узнай свой numeric id (`@userinfobot`).
3. Окружение:

```bash
python3 -m venv ~/.dsh-tg/venv && ~/.dsh-tg/venv/bin/pip install aiogram
export TG_BOT_TOKEN="123456:AA..."          # от BotFather
export TG_ALLOWED_USERS="123456789"         # свои id через запятую — ПУСТОЙ = бот отклоняет всех
export TG_WORKSPACES="octo:$PWD,home:$HOME" # имя:путь через запятую
~/.dsh-tg/venv/bin/python agent-infra/stack/tg/dsh_tg.py
```

`up.sh` делает то же самое в отдельном пейне, если `TG_BOT_TOKEN` задан.

### Использование

`/start` → карточка прикреплённой сессии: воркспейс, модель, доп. настройки,
«открепить». Дальше просто пишешь задачи текстом — они уходят в прикреплённую
сессию. `/sessions` (и кнопка «≡ сессии») показывает список: у каждой строки
свой значок — `⏳` крутится, `·` свободна.

**Сессии.** Как вкладки на десктопе: несколько живут в одном боте, новая
наследует настройки предыдущей, переключение — тап по строке списка,
«📌 открепить» отвязывает текст от сессии, не трогая её прогон. Пока
сессия не прикреплена, бот на текст отвечает списком, а не запуском.

**Чей это ответ.** Ответ приходит **ответом на ту самую задачу** (Telegram
покажет цитату) и с шапкой `#<id> <название>`, если сессий больше одной.
Иначе при двух параллельных прогонах не отличить, кто именно ответил.

**Жив ли он.** На каждую задачу бот шлёт одну плашку и дальше её
**редактирует** раз в `DSH_TG_PROGRESS` секунд (по умолчанию 15) —
редактирование не звенит нотификацией, поэтому виден ход времени, номер шага
и последнее событие, а телефон молчит. По завершении плашка превращается в
строку итога, а текст ответа приходит отдельным сообщением.

**Что умеет какой раннер** — разное, и бот об этом не врёт:

| | `cli` (по умолчанию) | `sdk` |
|---|---|---|
| память между задачами сессии | **нет**: headless на каждую задачу поднимает свежего агента | есть, пока жив рантайм |
| номер шага и активность | нет — виден только таймер | есть, из событий рантайма |
| «⏹ остановить» | есть (убивает прогон) | нет |
| усилие / права / инструменты | применяет | ⚠️ задаются его cordis-композицией (`DSH_TG_CORDIS`) |

Кнопка в «⚙️ доп. настройки», помеченная `⚠️`, — это настройка, которую
текущий раннер не применяет; бот её показывает, но не делает вид, что она
доехала.

**Доп. настройки** (значения сверены с пакетами проверенной ревизии):

| Настройка | Значения | Чем задаётся в `cli` |
|---|---|---|
| усилие | `off` / `high` / `max` | `--patch`: `reasoningEffort` ряда `llm-deepseek` |
| инструменты | `native` / `code` / `both` | `DSH_TOOLS_MODE` → `mode` ряда `tools` |
| права | `read-only` / `workspace-write` / `danger-full-access` | `DSH_PERMISSION_MODE` → пресеты ряда `permission` |

«По профилю» = бот не навязывает ничего, решает профиль или композиция.

Необязательное окружение: `DSH_TG_RUNNER` (`cli`/`sdk`), `DSH_TG_TIMEOUT`
(секунды, 900), `DSH_TG_PROGRESS` (секунды, 15), `DSH_TG_CORDIS` (путь к
cordis-композиции для `sdk`), `TG_MODELS` (список `provider/model`).

### Проверка без Telegram и без модели

```bash
~/.dsh-tg/venv/bin/python agent-infra/stack/tg/smoke_dsh_tg.py
```

Гоняет оба раннера на заглушке вместо `dsh`: сессии, клавиатуры, плашка,
оверлей и env, счётчик шагов; в конце — негативный контроль (проверка обязана
падать на сессии без настроек).

### Безопасность — прочитай

- **Агент имеет bash на твоей машине.** `TG_ALLOWED_USERS` обязателен;
  пустой список = бот отклоняет всех (fail-closed).
- Токен бота — секрет уровня SSH-ключа: в env, не в файлы репозитория.
- Один воркспейс = одна директория из белого списка `TG_WORKSPACES`;
  произвольные пути с телефона задать нельзя.

## 5. Телефон: три слоя удалённого доступа

| Слой | Что даёт | Что нужно |
|---|---|---|
| TG-бот | задачи dsh с телефона, ноль настройки сети | токен + запущенный `up.sh` |
| Herdr reattach | полноценные терминалы стада с телефона | SSH-клиент (Termius/Blink) + Tailscale до машины, затем `herdr session attach <name>` |
| dsh web UI | родной интерфейс с телефона | SSH-туннель `ssh -L 3081:127.0.0.1:3081 <mac>` через тот же Tailscale |

Порядок именно такой: бот — сразу, Tailscale — один вечер, туннель — бонус.
**Проброс web-порта наружу запрещён дизайном** — UI слушает localhost,
и это не надо «чинить»: удалённый доступ — только через SSH/VPN-слой.

## 6. Оверрайды прогона: модель, усилие, права, инструменты

У самого headless-приложения ровно два элемента командной строки — текст
задачи и `--help`; ни модели, ни сессии, ни формата вывода там нет. Всё
остальное едет либо патч-оверлеем профиля, либо переменной окружения,
которую читает композиция.

**Модель** — ряд `agent-default-model` (значение по умолчанию берётся из
`$DSH_HOME/settings.yaml`):

```bash
cat > /tmp/m.yml <<'EOF'
- id: agent-default-model
  config:
    provider: deepseek-official
    model: deepseek-v4-flash
EOF
dsh --profile headless --patch /tmp/m.yml "задача"
```

Провайдер именно `deepseek-official` — это маршрут родного адаптера
`dsh-llm-deepseek`. Имя `deepseek` принадлежит каталогу pi-ai и молчит,
пока в `settings.yaml` нет секции `llm-pi-ai:`.

**Усилие рассуждения** — там же, рядом с моделью:

```yaml
- id: llm-deepseek
  config:
    reasoningEffort: max     # off | high | max; без значения — high
```

**Права и подача инструментов** — переменные окружения прогона:

| Переменная | Значения | Что делает |
|---|---|---|
| `DSH_PERMISSION_MODE` | `read-only` / `workspace-write` (умолчание) / `danger-full-access` | пресеты ряда `permission`: режим песочницы + политика подтверждений |
| `DSH_TOOLS_MODE` | `native` (умолчание) / `code` / `both` | `mode` ряда `tools`: обычные схемы инструментов, Code Mode или оба |

Важное следствие для headless: встроенного «спрашивателя» у него нет —
политика `ask` без ответчика **закрывается**, то есть действие, требующее
подтверждения, просто не выполнится. Хочешь, чтобы прогон с телефона мог
всё — это `danger-full-access`, и это осознанный шаг, а не галочка.

**Сессий у headless нет.** Каждый прогон создаёт свежего персистентного
агента: между двумя задачами контекст не переезжает. Непрерывная сессия
есть у python-SDK (`deepseek-harness-sdk`): рантайм держится процессом,
сессия адресуется своим id, события прилетают в `on_notification` — на этом
у бота держатся и память сессии, и номер шага. Цена: у встроенной
композиции SDK нет ни песочницы, ни подтверждений (`bash-local`), поэтому
`DSH_PERMISSION_MODE` там ничего не значит — режим задаётся своим
cordis-файлом.

Проверка без запуска LLM: `dsh --profile headless --patch /tmp/m.yml --dump-config`.

## 7. Что где смотреть при проблемах

- `herdr status` — жив ли сервер, совместим ли протокол;
- `herdr pane read <id> --source recent-unwrapped --lines 120` — лог панели;
- `herdr agent list` — кого стадо видит и в каком статусе;
- web-панель молчит — `curl -s http://127.0.0.1:3081` и лог её пейна;
- бот молчит — лог пейна бота: отклонённые user_id печатаются именно туда;
- нотификация делегирования не приходит, в ответе `chat not found` — ты ни
  разу не нажал `/start` у бота: Telegram запрещает ботам писать первыми;
- `CERTIFICATE_VERIFY_FAILED` в python-скриптах — пустой trust store
  framework-питона на маке; обвязка поэтому ходит в Telegram через curl.
