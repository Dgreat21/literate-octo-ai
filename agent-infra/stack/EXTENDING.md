# EXTENDING — как расширять этот репозиторий

Гайдбук на сквозном примере: домен `agent-infra/` заводился ровно этими
шагами, каждый пункт можно сверить с фактом в git-истории.

## 1. Завести домен

```bash
cp -R example-domain/ <имя-домена>/
```

- Перепиши `README.md`: что за направление, карта файлов, префикс трекера.
- Добавь строку в таблицу доменов `AGENTS.md` §1 **тем же коммитом**.
- Если в имени домена дефис — префикс трекера без него (`agent-infra` → `INFRA`).

*Кейс: `agent-infra/README.md`, строка в AGENTS.md §1.*

## 2. Положить артефакты

Артефакты направления живут в домене (rule-1: артефакт или не было).
Инструкция — **одним файлом**, README только ссылается (rule-3: один
источник истины). Черновики диздоков — на кухню `mastery/design_docs/`,
не в домен.

*Кейс: `agent-infra/stack/herdr-dsh-instruction.md` — единственный источник по стеку;
черновик диздока `mastery/design_docs/herdr_dsh_stack.md`.*

## 3. Зарегистрировать скиллы

Каждому повторяемому приёму — строка в `mastery/registry.csv`:
ключ `MST-<id>` (автоинкремент, пропуски честные — ключи не
переиспользуются), триггер отвечает «когда включать», путь ведёт к
инструкции. Применил скилл — строка в `mastery/usage_log.csv` под локом.

*Кейс: MST-30 `herdr-report`, MST-31 `dsh-headless-job`, MST-32 `dsh-tg-remote`.*

## 4. Завести цель и задачи

В `mastery/tracker/`: задачи с префиксом домена, проект в `goals.csv`,
связи — рёбрами в `links.csv` (ребро пишется один раз). Статусы двигаются
по факту, закрытие — с резолюцией.

*Кейс: `PRJ-2` + `INFRA-1..6`, связи «входит в»/«блокирует».*

## 5. Опубликовать

Наружу — только осознанным актом владельца (rule-9): симлинк диздока в
витрину `design_docs/`, симлинк зачастившего скилла в `skills/`.
Агент предлагает — владелец кладёт.

## 6. Проверить и записать

```bash
python3 mastery/tools/check_refs.py     # битые ссылки после реорганизации (rule-8)
python3 mastery/tools/check_skills.py   # целостность скиллов by_team
python3 mastery/tools/skill_stats.py    # новые скиллы видны в боевой метрике
```

Каждая сессия работы оставляет строку в `work_journal.md` (append-only,
под локом) — включая ту, в которой ты сейчас читаешь этот файл.
