# Hearth — мобильный клиент harness'а

> *«The harness at home, held at arm's length.»*

Присмотр за домашним harness'ом с телефона (трек B/E домена, тикеты
`INFRA-7`, `INFRA-11`). Телефон — **окно, а не рабочее место**: «жив ли»,
«что говорит», «стоп». Всё дорогое остаётся на ноутбуке.

| Что | Где | Статус |
|---|---|---|
| Дизайн-макет: 9 экранов + варианты 1b–1g | [`Hearth.html`](Hearth.html) | открывается двойным кликом, без сети |
| Демон-агрегатор поверх herdr | [`hearthd/hearthd.py`](hearthd/hearthd.py) | v0 работает |
| Приложение (PWA, 4 экрана) | [`app/`](app/) | v0 работает |
| Запуск | [`bin/hearth-up`](bin/hearth-up) | |

## Запуск

```bash
agent-infra/hearth/bin/hearth-up
```

Печатает адрес вида `http://192.168.x.x:8788/#t=<токен>`. Открыть его в
Safari на телефоне (та же wifi) → «Поделиться» → **«На экран Домой»**.
Дальше это иконка, полноэкранный запуск, свой значок в переключателе —
установка без App Store и без ревью.

Токен лежит в `~/.hearth/token`, живёт между запусками; в URL передаётся
фрагментом (`#t=…`), поэтому не попадает в логи сервера — приложение
кладёт его в `localStorage` и дальше шлёт заголовком.

`--local` — слушать только loopback (проверить на маке).

### Ограничение: по LAN нет secure context

`http://192.168.x.x` — не защищённый контекст, поэтому **service worker там не
регистрируется** (исключение сделано только для `localhost`). Проверено:
`window.isSecureContext === false`, `navigator.serviceWorker` отсутствует.

Что это значит на телефоне:

- «На экран Домой» **работает** — iOS не требует service worker для установки,
  ему хватает манифеста и `apple-mobile-web-app-capable`. Приложение ставится
  и запускается полноэкранно.
- Не работает только кэш оболочки: без сети телефон покажет ошибку Safari
  вместо экрана «hearth unreachable». Честно, но некрасиво.
- На данные это не влияет никак: `/api/*` и так network-only.

Лечится HTTPS. Практичный путь — `tailscale serve`: он выдаёт настоящий
сертификат на имя в tailnet, то есть `INFRA-5` покупает не только доступ
снаружи, но и secure context. Это второй, независимый аргумент за него.

## Что показывает v0

Четыре экрана — ровно те, что оставлены резом `INFRA-7 §4`:

| Экран | Вопрос | Источник |
|---|---|---|
| **home** | жив ли, что делает, стоп | `herdr pane list` + хвост рабочего пейна |
| **log** | что говорит | `herdr pane read` — сырой хвост |
| **panes** | что вообще есть | `herdr pane list` — все пейны, не только распознанные агенты |
| **settings** | чем именно я связан и насколько свежи цифры | состояние связи |

Стоп — hold 700 мс с кольцом (вариант `1c-ii`), «дышащее» кольцо на home
(`1e-ii`). Экранов approvals, compose, machine, artifacts нет — см. рез §4.

**Важное свойство источника.** `working/idle/blocked/done` — это жизненный
цикл *агента* в понимании herdr: он приходит от распознавания агентов и от
`pane report-agent` (тот же механизм, которым репортит `bin/dsh-herdr`).
Обычная команда в шелле агентом не считается и висит как `unknown` — Hearth
показывает `unknown`, а не додумывает «работает». Хочешь, чтобы прогон
светился на телефоне, — он должен репортить статус, как это уже делает
headless-обёртка `INFRA-3`.

## Инвариант: приложение не врёт о связи

Ревью `INFRA-7 §3` нашло, что в макете инвариант был декларацией — в
состоянии не было ни одного поля связи. В коде он сделан структурой:

- **Состояние связи — поле модели**, три значения: `live` (< 6 с),
  `stale` (< 25 с), `unreachable`. Первая строка первого экрана —
  оно же.
- **Каждый ответ `hearthd` несёт `as_of`.** Как только связь не `live`,
  все цифры на экране получают приписку «as of N s ago».
- **Лог замирает с отметкой** «— stream broken at HH:MM —», а не
  продолжает ехать. Лог, который идёт при мёртвой связи, — самая опасная
  ложь из возможных.
- **Никаких оптимистичных апдейтов.** «Стоп» не считается выполненным
  потому, что мы нажали: кнопка держит «sent · waiting for herdr», пока
  herdr не покажет, что пейн сошёл с `working`; через 15 с — честное
  «sent, still working — check the mac». Провал отправки — «not sent».
- **Service worker кэширует только оболочку.** `/api/*` — network-only
  без фолбэка: офлайн обязан выглядеть как офлайн (DoD `INFRA-11`).
- **Ошибка различается.** «Мак не отвечает» и «мак отвечает, herdr — нет»
  — разные строки, потому что чинятся по-разному.

Мёртвая кнопка лучше молча пропавшей команды: при не-`live` связи все
контролы видимо гаснут (`opacity .34`, `disabled`), а не исчезают.

## API `hearthd`

Читающий агрегатор + одна пишущая ручка. Стандартная библиотека, без
зависимостей. Все ответы — JSON с `as_of` и `as_of_iso`.

| Ручка | Что делает |
|---|---|
| `GET /api/health` | жив ли сам демон |
| `GET /api/state` | пейны стада: статус (`working/idle/blocked/done/unknown`), cwd, заголовок |
| `GET /api/agent/<pane>?lines=N` | сырой хвост пейна (ANSI вычищен) |
| `POST /api/agent/<pane>/stop` | `ctrl+c` в пейн; отвечает статусом **после** отправки, не обещая результат |

При недоступности herdr — `503` с кодом (`herdr_missing`, `herdr_timeout`,
`herdr_failed`), **не** последний удачный ответ: закэшированный ответ был бы
ровно той ложью, против которой весь дизайн.

## Чего в v0 нет — и почему

- **Дайджест шагов (`1b-iii`).** Выбран автором и подтверждён ревью, но
  требует потока событий (`approval/*`, tool-calls dsh), а не парсинга
  лога. Сейчас честно показан сырой хвост с явной пометкой.
- **Очередь approvals.** `INFRA-7 §2, Р2`: headless-прогоны fail-closed,
  очереди в v0 физически нет. На home есть строка «N agents need a
  decision» и всё.
- **Нотификации** («went quiet», «нужно решение»). Web push в iOS-PWA
  возможен, но требует отдельной работы — `INFRA-10`.
- **Доступ вне дома.** Нужен Tailscale (`INFRA-5`) — жёсткий блокер,
  признан в ревью. Внутри домашней wifi всё работает уже сейчас.
- **Навигация (`1g`).** Вопрос был снят резом: на четыре экрана таббар —
  очевидная форма, спорить не о чем.

## Разработка

Правишь `app/` — подними версию кэша в [`app/sw.js`](app/sw.js)
(`hearth-shell-vN`), иначе телефон продолжит показывать старую оболочку.

Шрифты (`Caprasimo`, `Figtree`) и палитра «Organic» вынуты из макета и
лежат локально: приложение не ходит в сеть вообще.
