# Hearth — мобильный клиент harness'а: дизайн

> *«The harness at home, held at arm's length.»*

Дизайн-прототип iOS-приложения для присмотра за домашним harness'ом с
телефона (трек B домена, тикет `INFRA-7`). Автор макета — Денис.
Один самодостаточный файл: **[`Hearth.html`](Hearth.html)** — открывается
двойным кликом, без сети и сборки (шрифты и React вшиты).

## Что внутри

Модель: один мак в tailnet, на нём DeepSeek-эндпоинт и агентский цикл;
телефон — **окно, а не рабочее место**: «жив ли», «что говорит», «стоп»,
«разрешаю», «пришли файл». Всё дорогое остаётся на ноутбуке.

Главный инвариант дизайна: **приложение никогда не врёт о связи** —
состояние tailnet — первая строка первого экрана, при недоступности машины
все контролы гаснут видимо. Лучше мёртвая кнопка, чем молча пропавшая
команда.

| Секция | Что показывает |
|---|---|
| `1a` | рабочий кликабельный прототип: 9 экранов (home, runs, compose, approvals, machine, detail, settings…), живой лог, hold-to-approve, kill, retry |
| `1b` | live-лог: raw tail / step digest / **digest + одна сырая строка** (выбор автора) |
| `1c` | стоп: tap / **hold 700 мс с кольцом** / slide |
| `1d` | approve: две кнопки / **hold-to-allow, tap-to-deny** (в 1a) / swipe |
| `1e` | «жив ли»: heartbeat-точка / дышащее кольцо / tok/s-спарклайн / шаги-сегменты |
| `1f` | lock screen как главная поверхность: approval с локскрина, «hearth went quiet» — один алерт |
| `1g` | навигация: три формы для девяти экранов |

Варианты атомарные — «mix and match by id» (например, «лог из 1a заменить
на 1b-iii»).
