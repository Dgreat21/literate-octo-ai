# rules — устав

Уставные правила работы в `.context/` и вокруг него: то, что действует всегда,
независимо от задачи, домена и настроения. По файлу на правило: `rule-<id>.md`
(id — автоинкремент, не переиспользуется; про `#` в имени — см. ниже).

Отличие от AGENTS.md: **устав говорит «что нерушимо», AGENTS.md — «как именно».**
Механика (форматы, пути, команды) живёт в AGENTS.md и может меняться;
правила — принципы, они переживают реорганизации.

| Правило | Суть |
|---|---|
| [rule-1](rule-1.md) | Артефакт или не было |
| [rule-2](rule-2.md) | Журнал append-only |
| [rule-3](rule-3.md) | Один источник истины |
| [rule-4](rule-4.md) | Помечать, не удалять |
| [rule-5](rule-5.md) | Общие файлы — под локом |
| [rule-6](rule-6.md) | История не переписывается |
| [rule-7](rule-7.md) | Цифра рождается в источнике |
| [rule-8](rule-8.md) | После реорганизации — check_refs |
| [rule-9](rule-9.md) | Публикация — осознанный акт |
| [rule-10](rule-10.md) | Устав меняется явно |

## Жизненный цикл правила

- Новое правило: файл + строка в этой таблице + запись в журнал — по rule-10
  только решением владельца.
- Изменение: правка файла с новой датой в тексте; смысловой разворот — лучше
  новое правило, старое помечается устаревшим (rule-4).
- В имени файла дефис, а не `#` из первоначального эскиза: `#` — спецсимвол
  шелла и якорь в markdown-ссылках, файлы с ним вечно требуют экранирования.
